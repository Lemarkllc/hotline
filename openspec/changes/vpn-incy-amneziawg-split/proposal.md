# Proposal

## Why

Сотрудники, получающие VPN через бота («Получить VPN»), сейчас имеют только Xray-серверы (VLESS/Hysteria2). У части провайдеров эти протоколы работают нестабильно, а AmneziaWG — устойчивый к блокировкам WireGuard — на нашей панели уже поднят (inbound `915`, «AMN»), но в подписку сотрудникам не попадает. Приложение INCY умеет принимать AmneziaWG прямо из подписки (так делает соседний провайдер VPNbyte через свой `incy_merge.py`), но только если подписка собрана специально под него — наш прокси этого не делает.

Второе: у AmneziaWG нет клиентского роутинга по geoip — «российское напрямую» для него можно сделать только через `AllowedIPs` в самом конфиге. Без этого весь трафик сотрудника, включая российские сервисы и корпоративные ресурсы, пойдёт через зарубежный сервер. Плюс для INCY на панели выключена выдача Routing-профиля (`subIncyEnableRouting: false`) — даже Xray-серверы в INCY сейчас гонят RU-трафик через VPN.

## What Changes

- Прокси подписки (`GET /api/v1/vpn/sub/:subId`) распознаёт INCY по User-Agent и дописывает в JSON-ответ панели элемент `{"type":"amneziawg","version":1,"servers":[…]}` с нативными AmneziaWG-конфигами. Для Happ и прочих клиентов ответ не меняется (кроме уже существующих правок Profile-Title/Routing).
- В каждый выдаваемый AmneziaWG-конфиг подставляется вычисленный `AllowedIPs` — «весь интернет минус RU и локальные сети» (RU IPv4 укрупнён до /19, чтобы конфиг помещался в лимит iOS NetworkExtension), при этом сети Telegram и наши корпоративные адреса, которые в Routing-профиле идут через прокси, всегда остаются в туннеле; публичный IPv6 — в туннеле (защита от утечки).
- Список RU-сетей берётся из уже зеркалируемого нами `geoip.dat` (`vpnGeoDataService`) — без обращения к диску панели.
- Слоты AmneziaWG по устройствам: один WireGuard-ключ нельзя использовать с двух устройств одновременно, поэтому каждому устройству (по `X-HWID`) выдаётся свой стабильный слот. Слот 1 — основной клиент сотрудника, слот 2 — скрытый вспомогательный клиент панели `<panelEmail>-AWG2`, привязанный только к AmneziaWG-inbound. Привязка «хеш HWID → слот» хранится у нас в БД (сырой HWID не сохраняется).
- Новые VPN-профили получают AmneziaWG-inbound в наборе `VPN_STANDARD_INBOUND_IDS`; существующим профилям inbound добавляется разовым бэкфиллом.
- Увольнение (`vpnService.revokeProfile`) удаляет с панели и вспомогательный AWG-клиент, иначе у уволенного оставался бы рабочий ключ.
- AmneziaWG — опциональная часть подписки: любой сбой (нет слота, нет конфига, ошибка расчёта маршрутов) отдаёт обычную подписку без AmneziaWG, а не ошибку.
- Настройка панели (не код): включить `subIncyEnableRouting` с тем же профилем «RU напрямую», чтобы Xray-серверы в INCY тоже получили раздельную маршрутизацию.

## Capabilities

### New Capabilities
- `vpn-subscription`: выдача VPN-подписки сотруднику через наш прокси — AmneziaWG для INCY, раздельная маршрутизация «RU напрямую» для AmneziaWG, слоты AmneziaWG по устройствам, жизненный цикл вспомогательных AWG-клиентов (создание, отзыв при увольнении).

## Impact

- **Код API**: `services/vpnService.ts` (прокси подписки, создание/отзыв профиля), `services/vpnPanelService.ts` (создание вспомогательного клиента, привязка к inbound, получение сырой подписки), `services/vpnGeoDataService.ts` (переиспользование кеша `geoip.dat`), `config/vpnConfig.ts` (ID AmneziaWG-inbound, константы маршрутизации), новые чистые утилиты (парсер `geoip.dat`, расчёт `AllowedIPs`, декодер `vpn://`), новый репозиторий слотов.
- **БД**: новая таблица слотов AmneziaWG (Prisma-миграция), связь с `VpnProfile`.
- **Панель 3X-UI**: новые вспомогательные клиенты `*-AWG2` на inbound `915`; включение Incy-роутинга в настройках подписки; существующие клиенты получают inbound `915`.
- **Нагрузка**: разбор 16 МБ `geoip.dat` и расчёт ~10 тыс. маршрутов — раз на обновление файла (кеш), не на каждый запрос; ответ INCY вырастает примерно на 150–200 КБ на каждый AWG-конфиг.
- **Клиенты**: только INCY видит изменения; Happ, v2rayNG и т.п. — без изменений.
- **Зависимость от ветки**: строится поверх `fix/vpn-routing-onadd` (та же функция прокси).
