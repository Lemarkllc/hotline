# Design

## Context

См. proposal.md. Сейчас: `userService.requestDataConfirmation` шлёт TELEGRAM-уведомление `confirm_data_request`, бот ставит `session.awaitingFullNameCorrection` и применяет следующий текст через `fixFullNameSelf`. Блокировка — единая точка `userService.blockUser(admin, userId, reason)`: статус, уведомление `employee_terminated` (бот удаляет из чатов), `vpnService.revokeProfile`, аудит. Периодика — `setInterval` в `server.ts`. Мобильная оболочка — `MobileShell` + `MobileTabBar` (до 7 вкладок).

## Goals / Non-Goals

**Goals:** срок/напоминание/блокировка без участия человека; обработка заявок с телефона; одна точка правды для блокировки.

**Non-Goals:** подтверждение других полей кроме ФИО; кнопка «Подтвердить данные» в мобильной версии (страница «Пользователи» остаётся десктопной); изменение прав (кнопка — по-прежнему `user.manage`).

## Decisions

1. **Состояние — поля на `User`**, не отдельная таблица: одна активная проверка на человека, повтор перезаписывает. `dataConfirmationRequestedById` — кому слать итог. Альтернатива «таблица запросов с историей» избыточна: история есть в аудите.
2. **Обработка сроков — `setInterval` 10 мин** (как SLA лидов): точность до минут достаточна для «за 5 часов» и «2 дня». Выборки идемпотентны (`remindedAt` ставится после отправки, блокировка снимает срок).
3. **`blockUser` получает исполнителя `AuthenticatedUser | null` и вид уведомления** (`terminated` | `data_unconfirmed`) — та же единая точка (статус, VPN, аудит), меняется только сообщение сотруднику. В боте оба типа переиспользуют одно удаление из чатов. Аудит с `actorId = null` и `metadata.system = "data_confirmation_deadline"`.
4. **Кнопка «Данные верны» — callback в боте → бот-эндпоинт** `POST /users/confirm-data-bot` (как `fix-full-name-bot`); сервер решает, есть ли активный срок (идемпотентно). Присланное ФИО через `fixFullNameSelf` тоже снимает срок.
5. **PWA: баннер в `MobileShell`**, а не на Главной: мобильный дашборд показывает отчёты и может быть недоступен Администратору без `report.read`; баннер в оболочке виден на любой вкладке. Вкладку не добавляем — таб-бар уже до 7 пунктов.
6. **Уведомление о новой заявке** — WEB + push HRD и Администраторам (`access_request_new`), навигация на `/access-requests` (маршрут уже пускает HRD или `user.manage`).

## Risks / Trade-offs

- [Сотрудник не видит сообщения (бот заблокирован у него)] → блокировка всё равно наступит; запросивший получит уведомление и может разблокировать.
- [API был выключен в момент срока] → обработка при следующем тике: блокировка/напоминание выполнятся с опозданием, но выполнятся.
- [Напоминание и блокировка в одном тике, если срок <5 ч уже при первом тике] → правило: если срок истёк — только блокировка, без напоминания.

## Migration Plan

Аддитивная миграция `User`; деплой API, бота и веба. Уже отправленные «старые» запросы без срока не затрагиваются.
